# mock-django

1. Клонировать репозиторий
2. docker compose up -d --build
3. Перейти в браузере на http://localhost:8080

# Roadmap находится в docs/deployment

## env.example

Шаблон файла переменных окружения.

Содержит пример настроек для запуска проекта: DEBUG, SECRET_KEY, ALLOWED_HOSTS, параметры подключения к PostgreSQL и другие значения.

Настоящий файл .env не хранится в репозитории, так как он может содержать секретные данные. Для локального запуска или развертывания нужно создать .env на основе .env.example.

## .gitignore

Файл с правилами исключения из Git.

В нем указано, какие файлы и папки не должны попадать в репозиторий: временные файлы Python, кэш, локальные настройки IDE, файл .env, резервные копии базы данных и другие служебные артефакты.

## .gitlab-ci.yml

Пример конфигурации GitLab CI/CD pipeline.

Файл показывает, как можно автоматизировать проверку, тестирование, сборку Docker-образа и развертывание проекта.

Pipeline включает стадии:

validate — проверка корректности Django-проекта;
test — запуск миграций и тестов;
build — сборка Docker-образа;
deploy — ручное развертывание на staging или production-like окружение.

Так как основной репозиторий находится на GitHub, этот файл используется как проектный артефакт для демонстрации переноса схемы GitLab CI/CD. Для фактического запуска pipeline проект нужно импортировать или зеркалировать в GitLab.

## deploy/

Папка содержит технические файлы, которые демонстрируют возможную реализацию production-like развертывания проекта.

## deploy/docker-compose.prod.yml

Docker Compose конфигурация для production-like запуска проекта.

Описывает три основных сервиса:

web — Django-приложение, запускаемое через Gunicorn;
db — база данных PostgreSQL;
nginx — reverse proxy для обработки HTTP-запросов.

Файл показывает, как приложение может быть развернуто в контейнерной инфраструктуре.

## deploy/nginx/default.conf

Пример конфигурации nginx.

Описывает проксирование запросов к Django-приложению, работающему внутри Docker-сети. Также содержит отдельную настройку для endpoint /health/, который используется для проверки работоспособности приложения.

## deploy/scripts/deploy.sh

Скрипт развертывания приложения.

Выполняет основные действия:

собирает Docker-образы;
запускает базу данных;
применяет миграции Django;
собирает статические файлы;
запускает все контейнеры приложения.
deploy/scripts/backup-db.sh

Скрипт резервного копирования базы данных PostgreSQL.

Предназначен для создания backup перед релизом или перед выполнением потенциально рискованных изменений.

## deploy/scripts/rollback.sh

Скрипт отката к предыдущей версии проекта.

Позволяет вернуться к указанному git-тегу или commit SHA и повторно выполнить развертывание выбранной версии.

## docs/deployment/roadmap.md

Основной документ дорожной карты.

Описывает план внедрения схемы развертывания для проекта mock-django.

Включает этапы:

организационная подготовка;
подготовка репозитория;
техническая адаптация Django-приложения;
настройка GitLab CI/CD;
развертывание;
приемка и сопровождение.
docs/deployment/deployment-guide.md

Инструкция по развертыванию.

Описывает порядок локальной проверки, production-like запуска, применения миграций, резервного копирования и остановки контейнеров.

## docs/deployment/gitlab-ci-variables.md

Описание переменных GitLab CI/CD.

Перечисляет переменные, которые нужно настроить в GitLab для выполнения развертывания: SSH-ключи, адрес сервера, путь к проекту, URL окружений и другие параметры.

## docs/deployment/release-checklist.md

Чек-лист приемки и релиза.

Содержит список проверок перед релизом, во время релиза и после него. Нужен для того, чтобы развертывание проходило не хаотично, а по заранее определенной процедуре.

## docs/deployment/rollback-plan.md

План отката.

Описывает, что делать, если после релиза приложение не запускается, endpoint /health/ не отвечает, миграции прошли некорректно или возникли другие критичные ошибки.

## docs/deployment/risk-register.md

Риск-регистр проекта.

Содержит список возможных рисков при внедрении развертывания, их влияние и меры снижения. Например: попадание секретов в репозиторий, проблемы с PostgreSQL, ошибки миграций, конфликт портов, отсутствие стратегии отката.

## docs/deployment/settings-fragment.md

Пример фрагмента настроек Django для production-like окружения.

Показывает, как можно читать SECRET_KEY, DEBUG, ALLOWED_HOSTS, параметры PostgreSQL и другие настройки из переменных окружения.
